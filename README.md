# Solar Flow

一个本机优先的人民币个人记账 PWA。流水导入在浏览器本地解析，常用功能可离线使用。

## 当前版本

- 离线可用：流水和设置存储在浏览器本机，Service Worker 缓存应用壳。
- 手动记录：只记录支出和收入，日期默认当天，资金类型默认“生活资金”。
- 总资产单一口径：不建立微信、支付宝或银行卡账户；不同账单来源只用于去重，跨来源互转会在收入/支出净额中自然抵消。
- 多账本：测试、真实记录和阶段性记录可以新建独立账本，彼此不沿用数据；每个账本都支持设置总资产、清空和最近 30 次撤销。
- 新账本从 0 开始：总资产、五种资金和交易记录都是 0；用户设置总资产后，才从当日起计算当前余额变化。
- 账单导入：XLSX、XLS、CSV、OFX 入口；导入前预览，支持按流水号、精确指纹和日期/金额/商户近似匹配。
- 趋势与构成：今天、近 7 天、本月、近 3 个月、近 6 个月、本年度。
- 资金分配：自由资金、紧急资金、生活资金、计划资金、其他资金。
- 借款与信用：信用卡、借款和分期是轻量待还清单，记清楚后可直接划掉，不绑定流水账户。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://127.0.0.1:5173/solar-flow/`。

生产构建：

```bash
npm run build
```

## 导入规则

每次导入都先选择账单来源标签。来源标签只用于区分两个微信或两个支付宝的导出文件、避免重复，不会生成账户或拆分总资产。

处理顺序是：同来源流水号重复 → 同来源精确指纹重复 → 日期 ±2 天且金额/方向/商户高度相似时匹配手动记录 → 其余作为新记录；“金额和日期接近但商户不一致”的行会留在需确认状态，不会静默写入。早于资产起算日的历史流水只进入统计，不重复改变当前余额；起算日之后的流水才改变余额。微信账单会从第 18 行表头开始解析，支付宝 GBK/CSV 会从第 24 行表头开始解析；失败、关闭、撤销等中性记录会跳过。

## 同步说明

GitHub Pages 仅托管静态网页。跨设备同步使用 Firebase Authentication（邮箱/密码）与 Cloud Firestore，数据库区域为香港（`asia-east2`）。只有完成邮箱验证后才连接云端；每个 Firebase UID 只能访问自己的 `users/{uid}/records`，并通过 Firestore Security Rules 校验。首次连接会询问是否合并本机账本；离线时继续写入本机，联网后补传。上传的原始 CSV/XLSX 文件不会发送到云端，云端同步的是解析后的账本记录。计划封面图片仍保存在本机，暂不云同步。

此公开演示站的 Firebase 免费 Spark 方案有用量上限，不代表无限量或永久零成本；项目所有者目前未绑定付款方式或启用付费方案。访问者可以选择只在本机使用；启用同步前请先了解账本数据会存储在 Firebase 香港区域。Web app 配置属于公开客户端标识，访问控制由安全规则承担；服务账号密钥绝不能放进网页或仓库。

## 发布

仓库使用 GitHub Actions 构建并部署到 GitHub Pages，构建需要在仓库设置中配置以下 Actions Variables：`VITE_FIREBASE_API_KEY`、`VITE_FIREBASE_AUTH_DOMAIN`、`VITE_FIREBASE_PROJECT_ID`、`VITE_FIREBASE_APP_ID`、`VITE_FIREBASE_MESSAGING_SENDER_ID`。部署工作流会在变量缺失时停止，避免发布一个看似可用但无法登录同步的版本。

本地运行前复制 `.env.example` 为 `.env.local` 并填写同一组 Firebase Web app 配置。

## 数据原则

- 金额按“分”存储，避免浮点误差。
- 总资产由用户设置起始基线，再随收入和支出变化；导入的中性/失败流水不改变总资产。
- 支出余额顺序：生活资金 → 其他资金 → 自由资金 → 计划资金 → 紧急资金。只有生活资金与紧急资金有目标进度线；其他资金是总资产扣除已分配后的余额。
- 手动记录优先保留；导入只补充流水号、来源文件和原始类型。
- 导入批次会留下记录，后续可做撤销和审计。
